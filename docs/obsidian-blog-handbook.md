# 西泽博客 Obsidian 维护手册

更新时间：2026-05-15

这份文档是给你自己长期维护博客用的，目标是：

- 可以直接放进 Obsidian
- 能当成项目档案长期保存
- 能快速回顾博客现在是什么状态
- 能一步一步照着维护、发文、部署、排错

线上地址：

- 主站：`https://xize.ink/`

## 2. 现在的核心架构

当前是混合架构，不是纯静态，也不是纯数据库博客。

### 2.1 前台

前台仍然由 Astro 构建页面结构、布局和样式。

主要页面：

- 首页
- 文章页
- 归档页
- 搜索页
- 留言页
- 相册页
- 友链页

### 2.2 后台

后台 UI 文件：

- `public/admin/index.html`
- `public/admin/app.js`
- `public/admin/app.css`

后台 API 文件：

- `worker/index.js`

### 2.3 内容数据

当前实时内容主来源：

- GitHub 仓库 `master` 分支

也就是说后台保存文章后：

1. Worker 调 GitHub API
2. 修改仓库中的 Markdown 文件
3. 前台页面运行时从 Worker 接口拉最新内容
4. 页面在轮询间隔内自动更新

### 2.4 图片数据

当前图片上传的实际主存储：

- GitHub 仓库的 `public/uploads/`

当前访问方式：

- 统一走 `/media/...`

也就是说，虽然底层文件存 GitHub，但外部访问路径看起来像站内资源。

### 2.5 D1 和 R2 状态

代码里已经预留了：

- D1：用于未来实时文章数据库层
- R2：用于未来图片对象存储

但是当前线上真正启用的仍是：

- 文章：GitHub
- 图片：GitHub

原因不是代码没写，而是当前 Cloudflare 这边权限和资源还没完全开到那一步。

## 5. 本地维护流程

### 5.1 启动前台

```bash
pnpm dev
```

访问：

- `http://127.0.0.1:4321/`

### 5.2 启动本地后台

```bash
pnpm admin
```

访问：

- `http://127.0.0.1:8787/admin/`

### 5.3 前后联调一起开

```bash
pnpm dev:admin
```

这样会同时启动：

- 博客前台
- 本地后台

适合你做：

- 改配置
- 改样式
- 试文章
- 试图片上传
- 看前台实时效果

## 6. 线上后台发文流程

### 6.1 登录

打开：

- `https://xize.ink/admin/`

输入后台 Token。

后台状态说明：

- `未登录`：还没输入
- `Token 已填入，待验证`：浏览器记住了密码，但还没通过接口验证
- `认证成功`：接口验证通过，可以管理文章

### 6.2 新建文章

点：

- `新建文章`

填写：

- `Slug`
- `标题`
- `发布时间`
- `分类`
- `标签`
- `摘要`
- `Markdown 正文`

### 6.3 保存草稿 / 发布

可选按钮：

- `保存`
- `存为草稿`
- `发布`

建议实际习惯：

1. 先存草稿
2. 检查前台
3. 再点发布

### 6.4 删除

- 草稿可直接删
- 已发布文章删除时会有更强提示

## 7. 图片上传流程

这是你现在最关心的一块。

### 7.1 目前已经支持什么

当前后台已经支持：

- 选择本地图片文件
- 上传图片
- 自动把返回地址写入“封面图”字段
- 自动把正文图片 Markdown 插入到光标位置

### 7.2 怎么上传封面图

在后台编辑文章时：

1. 找到 `封面图`
2. 点 `上传封面图`
3. 选择本地图片
4. 等待上传完成
5. 后台会自动把地址填到 `封面图` 输入框里

返回格式通常是：

```text
/media/posts/年/月/文件名.png
```

### 7.3 上传后怎么生效

上传后：

- 封面图字段会自动填入图片地址
- 你继续保存/发布文章
- 前台轮询到新内容后，封面图会显示出来

### 7.4 怎么插正文图片

在后台正文编辑区：

1. 找到 `Markdown 正文`
2. 点 `上传正文图片并插入`
3. 选择本地图片
4. 后台会自动上传
5. 自动把类似下面的 Markdown 插入到当前光标位置：

```markdown
![图片名](/media/posts/2026/05/xxx.png)
```

你不需要自己再手抄图片地址。

### 7.5 图片现在存在哪里

当前线上实际存储：

- GitHub 仓库的 `public/uploads/...`

但访问走的是：

- `/media/...`

这样做的好处是：

- 上传后马上可访问
- 不用等静态构建后再出图片

### 7.5 这个上传方案的边界

当前更适合：

- 封面图
- 普通尺寸插图
- 低到中等频率的个人发文

当前还不适合：

- 大规模图床
- 高频海量上传
- 自动压图、多尺寸裁剪、图库管理

### 7.6 未来更好的方案

如果以后图片越来越多，建议升级为：

- Cloudflare R2 存图

升级后会更适合：

- 长期大量图片
- 更稳的对象存储
- 减轻 GitHub 仓库膨胀

但是现在这版已经够你正常发文使用。

## 8. 你现在还能怎么填“封面图”

除了上传按钮，现在仍支持手动填：

1. 相对路径
```text
./images/cover.webp
```

2. `public` 绝对路径
```text
/assets/covers/cover.webp
```

3. 外链
```text
https://example.com/cover.webp
```

4. 上传后自动生成的站内地址
```text
/media/posts/2026/05/xxx.webp
```

你今后最推荐用的是第 4 种。

## 9. 线上实时更新到底是什么程度

当前不是 WebSocket 秒推，而是轮询更新。

轮询间隔：

- `15000ms`

也就是大约 15 秒。

现在已经能实时到的部分：

- 首页文章列表
- 文章正文主内容
- 归档列表
- 文章元数据 API

还没有完全实时的部分：

- 搜索索引
- 某些构建期推荐块
- 部分统计

所以现在的真实体验是：

- 发文后十几秒内公开页通常就会变
- 搜索和极少数附属信息不会同步那么快

## 10. 本地和线上的区别

### 10.1 本地

本地后台改文章：

- 直接写 `src/content/posts`
- Astro 热更新
- 几乎立刻看到变化

本地上传图片：

- 写到 `public/uploads`
- 本地前台立刻能读

### 10.2 线上

线上后台改文章：

- Worker 写 GitHub
- 前台轮询读取 Worker 最新内容

线上上传图片：

- Worker 先写 GitHub
- Worker 通过 `/media/...` 立即提供访问

所以现在已经能达到：

- 线上也能边发边看

只是它和本地的机制不一样。

## 12. 当前还没彻底维护完的东西

这里是最重要的“未完成列表”。

### 12.1 D1 还没真正上

代码写了，但线上数据库没正式启用。

当前原因：

- Cloudflare Token 权限不够

后果：

- 实时内容层还在走 GitHub，而不是 D1

当前上传图虽然已经能用，但底层还是 GitHub。

后续如果图片越来越多：

- 应该迁到 R2

### 12.3 正文图片插入体验还不够好

现在封面图上传已可用，但正文还没有：

- 上传后自动插入 Markdown
- 图片列表管理
- 批量图片管理

### 12.4 搜索不是完全实时

当前搜索主要还是靠 Pagefind 构建索引，不是 Worker 动态搜索。

### 12.5 分类统计和部分推荐还不是完全实时

文章本体已经实时了，但附属统计类展示还没全部动态化。

### 12.6 评论系统还没最终定型

留言页存在，但评论方案仍适合后续正式选型。
